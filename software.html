Getting started

Install the alpha release.

pip install featuregraph

The alpha designation indicates that behavioral semantics and APIs are usable but still subject to refinement before a stable release. Release notes and archived artifacts identify the exact implementation used for the current research results.

Public API

Construct objects from a signal table.

import featuregraph as fg

data = fg.datasets.eastman(
    fault_number=1,
    simulation_run=1,
)

behavior = fg.oscillation.Oscillation(
    signals="reactor_temperature",
    group=["fault_number", "simulation_run"],
    smooth_signal=True,
    smooth_window=20,
)

features = behavior.fit_transform(data)
objects = behavior.summarize(
    features,
    signal="reactor_temperature",
)

The feature table preserves sample-level construction state, while the object table contains one row per constructed oscillation. This separation supports both inspection of the procedure and downstream reasoning over completed objects.

Architecture

One lifecycle, behavior-specific semantics.

Design principle

Construction remains visible.

FeatureGraph does not return only a final numerical embedding. Primitive states, transition events, identifiers, boundaries, measurements, and completeness can be examined independently, making it possible to understand why an object exists and how each property was calculated.

This inspectability is central to both scientific reproducibility and machine consumption. A later reasoning system can use explicit objects without obscuring the procedure that created them.

Included data access

Evaluation without manual dataset plumbing.

The release includes loaders for BIDMC physiological signals and the Tennessee Eastman industrial process dataset. The loaders provide stable entry points for reproducing examples, tests, tables, and figures while keeping the behavioral construction procedure independent of the source domain.

Research package

Code and evidence are released together.

The repository includes a reproducibility script and manifest for paper tables and figures, as well as environment and hardware capture for benchmark runs. The Zenodo record preserves the release independently of the evolving main branch.
